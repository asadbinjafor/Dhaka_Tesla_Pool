# Optional PDF bonus: reason about growth, without building it

This is design reasoning for 1M passengers/100k drivers, not a benchmark or extra deployed infrastructure. Current correctness uses PostgreSQL parent locks and persisted receipts across multiple API instances; tests prove two instances contending on one Bullet, not production scale/latency.

First measure active users, request frequency, p95 latency, DB connections/lock waits, slow queries, error/unknown-command rate and hot driver contention. Horizontal stateless Next/Nest behind a TLS load balancer can share DB sessions; use bounded connection budgets or a measured pooler instead of multiplying five connections per process indefinitely. Share abuse limits and expiry/session cleanup, protect credentials/CSRF and retain owner checks on every node. Deployment needs managed secrets, backups/restores, health-driven rollout and rollback-compatible numbered migrations.

Keep acceptance/current mutations on the primary: stale replicas cannot decide seat availability. Index active group/pickup queues and terminal actor/time/ID history, inspect query plans and partition/archive only after measured need. Owned history/reporting can use replicas with a declared freshness contract; avoid showing newly completed trips missing without explanation. Cache public route/catalog versions first; do not globally cache private ride/session DTOs. Denormalized aggregates need idempotent updates, reconciliation and a date/population definition before replacing current exact SQL.

For larger geography, introduce indexed spatial search (e.g. PostGIS) when zone compatibility fails actual product needs. Matching can become worker-assisted, but final seat assignment must still revalidate/lock parent resources and commit one membership/receipt. Per-driver serialized contention is intentional; avoid distributed in-memory mutexes as a substitute for DB invariants. A hot queue should use backpressure/timeouts and coherent conflict/retry responses, not guessed success.

Realtime SSE/WebSockets can reduce polling if connection count and operational cost justify them; after reconnect, refetch owned stable versioned state. Events/notifications may use a transactional outbox with idempotent consumers once reliable asynchronous effects exist. Never emit a business success event before the transaction commits. Trace safe correlation IDs across gateway/API/DB without logging session tokens, private fares for other users or request secrets. Audit access and test restore/security/retry paths alongside throughput tests.

Scale changes are triggered by measurements and simpler alternatives failing; Kafka/Kubernetes/Redis/queues are not currently installed merely to draw a larger diagram. The current MVP remains one modular API, one Next UI and PostgreSQL with reproducible Docker.
