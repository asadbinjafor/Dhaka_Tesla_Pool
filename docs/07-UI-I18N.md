# UI, Bangla/English, Dark/Light and charts — required user additions
Status: specification to implement; current reference is an English browser-local demo.
Source: user-selected additions; do not attribute language/themes/charts to the PDF.

## 1. Audit current UI before editing
Open reference/ui-dark-light/index.html and readable src with existing screenshots.
Inspect actual controls, mobile navigation, labels, color hierarchy, dialogs and states.
Record existing behavior vs PDF, and evidence of a defect vs an improvement suggestion.
Retain charcoal/deep-green/lime Dark mode and matched clean Light mode. Original source
stays read-only; implement corrections in modern app, not a second disposable redesign.
Photos/illustrations/selected UI do not authorize invented ETA, carbon, revenue,
battery, rating, match percent, fees, chat/SOS or specific numbered seat reservation.
Three passenger places indicate quantity/occupancy, not booking a numbered physical seat.

## 2. Required routes and screens
Route pattern (proposed, locale-specific display only): /[locale]/..., locale en|bn.
- /sign-in, /sign-up with language and theme switches before login.
- Passenger overview, book, current discovery, rides/[id], history, account/settings.
- Driver overview, requests, current discovery, pools/[id], trip history, vehicle,
  account/settings. Valid next actions and owned roster are preserved.
- Terminal detail, all confirmation dialogs, guide, empty/loading/error/unknown states.
Locale-prefixed stable ID pages keep the same ride/pool on switches and reload.
/api/v1 remains locale-neutral and is excluded from locale redirects. Validate locales;
unsupported prefixes must not become uncontrolled dictionary imports/open redirects.

## 3. Full translation coverage
Use typed/validated catalogs en.json and bn.json through a maintained compatible i18n
strategy chosen once in foundation. No scattered English strings in JSX or automatic
runtime translations. templates/messages is a seed catalog only; inventory all actual
product strings and extend it. App title/proper names/IDs may intentionally remain
unchanged; document them rather than pretending every identical string is a failure.

Translate: navigation, headings, buttons, labels/placeholders/help, validation errors,
auth/authorization failures, fare breakdown, ride statuses, cancellation reasons,
confirmation dialogs, toasts, tables/filters/pagination, graph axes/legends/tooltips,
empty/loading/offline/retry states, accessible names, theme/language labels, onboarding
and product 404/error surfaces. Native browser validation messages may follow browser
language instead of app locale; use a validated localized error experience and test it.
No raw Nest/SQL English errors in a Bangla UI. API codes+safe params map to catalogs.

Canonical IDs/enums stay stable (BANANI, REQUESTED, DRIVER, BDT etc). Use configured
zone translations e.g. Banani/বনানী, Mohakhali/মহাখালী, Gulshan 1/গুলশান ১. Do not
translate primary keys or alter user-supplied names/reasons. Render user text safely.
Known event/reason codes localize at view time; preserve raw user-entered reason text.

## 4. Independent controls, state and persistence
Visible বাংলা / English text switch (not country flags) plus Dark/Light control in
header/auth and mobile menu. Both languages have left-to-right layout. Proposed default
en; precedence explicit valid URL > valid preference cookie > en. Selected Dark default
unless an explicit saved theme. Document a different choice before implementing.
Set correct html lang; remember preferences without requiring authentication. For SSR,
use one validated source for initial locale/theme; avoid hydration mismatch/wrong-theme
flash. Do not access window/localStorage in Server Components or blanket suppress errors.

Language/theme switches are PRESENTATION changes, not domain mutations. Preserve current
stable ID, session, form draft, selected canonical zone/seat quantity, quote ID and
pending idempotency key, valid query filters and history position. Use shared state
above remounting locale boundaries or a session-scoped non-sensitive draft mechanism;
clear private drafts on logout. Never serialize credentials or shared user data to URL.
A valid quote must not be discarded simply due to locale/theme; expiry still applies.
Do not trigger auto-submit/refetch mutations when a dictionary loads. Switching during
unknown outcome must reconcile the same business action. Locale/theme excluded from
canonical idempotency hash; private response freshness still uses session/request/pool.

## 5. Dates, amounts, typography and numbers
Format display using Intl with en-BD/bn-BD, BDT and Asia/Dhaka; test actual runtime
support. Store UTC instants and integer poysha; no formatted numeral strings in amounts.
Choose an explicit decimal/zero-fraction rule consistently. Bengali localized numerals
are display; IDs/emails/code remain canonical. Accept ASCII and Bangla digits only for
numeric seat input if that input permits typing; normalize to integer and validate on
server. Never blanket-normalize passwords, free text or identifiers.
Use Bangla-capable licensed/system fonts with tested fallback, line height and conjunct
rendering. Do not include font binaries taken from an unrelated host/container. If a
font dependency is chosen for the app, obtain it legitimately and record its license.
Review বাংলা clipping, wrapping, mixed scripts, tables and small mobile controls.

## 6. Real charts, not decorative graphs
Passenger: own COMPLETED ride count, total final fare and pooling discount by day.
Driver: own COMPLETED pool count, seats served and seat utilization based on each
pool's capacity snapshot. Exclude canceled members/pools as specified; aggregate pools
before joining members to avoid denominator duplication. No driver income or paid cash
claims. Date filter population/timezone must be explicit and shared by table/card/chart.
Show correct no-data/zero/error/loading states, selected period and currency/unit.
Translate every chart label/tooltip/ARIA name; readable exact-data table; theme-aware
contrast and non-color-only legends. Charts are now required user scope; prioritize
core correctness first but complete graphs before claiming all requested scope done.

## 7. Acceptance matrix
Test every principal view in all combinations:
EN×Dark, EN×Light, BN×Dark, BN×Light; widths 360,390,768,1024,1440.
Record real screenshot/overflow/focus results, not a fake precomputed check count.
Run at least the full pooled journey and one cancellation in both locales, switching
mode/locale mid-form, matched ride, pending command and completed/canceled detail.
Maintain dictionary key/placeholder parity checks; missing/empty keys fail CI. A graceful
unknown-code fallback must not hide missing required translations in tests. Check en
fallback only where documented. Do not declare WCAG conformance from token pairs alone.

## 8. Demo-to-real removal
No end-user Preview as / Explore another perspective / public scenario/reset switches.
Own profile and sign-out replace demo selector. Use real Nest auth and serializers,
not hidden UI fields. Retain configured named seed users for local/evaluator testing;
no silent demo passwords in production. Logout must cancel reads and advance session
generation so old responses cannot display under a different account or language.
